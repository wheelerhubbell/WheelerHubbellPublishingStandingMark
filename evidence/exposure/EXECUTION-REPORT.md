## Recursive path and remaining dependencies

A caller may carry authorized exact Mark bytes in ordinary work. The next machine reads the Mark-bound discovery identity, resolves the signed current service, independently admits the root under its own policy, verifies historical meaning and fresh registry status, determines its own need for a different object, checks authority/profile prerequisites, and only then uses owner-authorized payment for a new evaluation. A positive assessment can yield a distinct new Mark. The handoff resource now exposes this path through HTTP links, MCP, the sitemap and llms.txt. No automatic forwarding, private-result publication or missing-Mark-to-buy-WHP rule was added.
